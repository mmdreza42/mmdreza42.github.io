🟢 Node.js

What is Node.js? Node.js is a JavaScript runtime built on Chrome's V8 JavaScript Engine. It allows JavaScript to run outside the browser and is designed for building fast, scalable, event-driven server-side applications.
What is the V8 Engine? V8 is Google's open-source JavaScript engine written in C++. It compiles JavaScript directly into native machine code using Just-In-Time (JIT) compilation, making JavaScript execution extremely fast.
What is libuv? libuv is the C library that powers Node.js asynchronous operations. It provides the Event Loop, Thread Pool, and asynchronous I/O, allowing Node.js to perform non-blocking file system, networking, DNS, and other operations.
Why is Node.js single-threaded? JavaScript execution runs on a single main thread. Instead of creating one thread per request, Node.js delegates I/O operations to libuv and the operating system, allowing the main thread to continue executing other tasks.
What is Event-driven architecture? Node.js follows an Event-driven architecture, meaning it responds to events such as HTTP requests, file reads, timers, or socket messages by executing their registered callbacks.
What is Non-blocking I/O? Non-blocking I/O means Node.js does not wait for I/O operations (database, file system, network) to finish. Instead, it delegates the operation to libuv and continues executing other JavaScript code.
What is the Event Loop? The Event Loop is the mechanism that enables Node.js to perform non-blocking operations. It continuously checks whether the Call Stack is empty. When it is, the Event Loop executes pending callbacks from its phases while also processing the process.nextTick() queue and the Promise microtask queue.
What are the Event Loop phases? The Event Loop consists of six phases: Timers → Pending Callbacks → Idle/Prepare → Poll → Check → Close Callbacks. Between phases, Node.js processes the process.nextTick queue and the Promise microtask queue.
What is the Call Stack? The Call Stack is the data structure where JavaScript executes synchronous function calls. Only one function executes at a time. The Event Loop starts processing asynchronous callbacks only after the Call Stack becomes empty.
What is a Microtask? A Microtask is a high-priority asynchronous callback. Promise callbacks (.then(), .catch(), .finally()), await, and queueMicrotask() are executed from the Microtask Queue before the Event Loop proceeds to the next phase.
What is a Macrotask? Macrotasks are asynchronous callbacks scheduled by APIs such as setTimeout(), setInterval(), setImmediate(), and I/O operations. They are executed by the Event Loop phases after all pending microtasks have finished.
What is process.nextTick()? process.nextTick() schedules a callback to execute immediately after the current operation finishes, before the Event Loop continues to the next phase. It has higher priority than Promise microtasks.
What is setImmediate()? setImmediate() schedules a callback to execute during the Check phase of the Event Loop. When used inside an I/O callback, it usually executes before setTimeout(fn, 0).
Difference between setTimeout() and setImmediate()? setTimeout(fn, 0) executes during the Timers phase after the minimum delay. setImmediate() executes during the Check phase. Their execution order is not guaranteed in the main module, but inside an I/O callback, setImmediate() usually runs first.
Concurrency vs Parallelism? Concurrency means handling multiple tasks by switching between them efficiently. Parallelism means executing multiple tasks at the same time using multiple CPU cores. Node.js is concurrent by default and can achieve parallelism using Worker Threads or Cluster.
CPU-bound vs I/O-bound tasks? CPU-bound tasks spend most of their time performing computations (image processing, encryption, video encoding). I/O-bound tasks spend most of their time waiting for databases, files, or network operations. Node.js performs best with I/O-bound applications.
What is asynchronous programming? Asynchronous programming allows a program to start a task without waiting for it to finish. While the task is running (e.g., reading a file or making an HTTP request), Node.js continues executing other code, improving responsiveness and scalability.
What is a callback? A callback is a function passed as an argument to another function that is executed after an asynchronous operation completes.
What is Callback Hell? Callback Hell occurs when multiple nested callbacks make code difficult to read, maintain, and debug. It can be avoided by using Promises or async/await.
What is a Promise? A Promise is an object representing the eventual result of an asynchronous operation. It has three states: Pending, Fulfilled, and Rejected.
Promise states? Pending → operation is still running.
Fulfilled → operation completed successfully.
Rejected → operation failed with an error.
What does async do? The async keyword makes a function always return a Promise. If the function returns a normal value, JavaScript automatically wraps it in a resolved Promise.
What does await do? await pauses only the current async function until the awaited Promise settles. It does not block the Event Loop or the entire Node.js process.
What is Promise.all()? Promise.all() executes multiple Promises concurrently. It resolves only if all Promises succeed, and rejects immediately if any Promise rejects.
What is Promise.allSettled()? Promise.allSettled() waits until every Promise finishes, regardless of whether they are fulfilled or rejected. It returns the status of each Promise.
What is Promise.race()? Promise.race() settles with the first Promise that completes, whether it resolves or rejects.
What is Promise.any()? Promise.any() resolves with the first fulfilled Promise. It rejects only if every Promise rejects.
What is queueMicrotask()? queueMicrotask() schedules a callback in the Microtask Queue. It runs after the current synchronous code completes but before the Event Loop proceeds to the next phase.
What is EventEmitter? EventEmitter is the core class that enables event-driven programming in Node.js. Objects can emit events using emit() and listen for them using on() or once().
Difference between on() and once()? on() registers a listener that executes every time the event is emitted. once() registers a listener that executes only once and is automatically removed.
What is Buffer? A Buffer is a global Node.js class used to work with raw binary data. Buffers are commonly used for file systems, streams, sockets, images, audio, and network communication.
What are Streams? Streams are objects that process data chunk by chunk instead of loading the entire data into memory. They improve memory efficiency and are ideal for large files and network communication.
Types of Streams? Node.js provides four types of streams: Readable, Writable, Duplex, and Transform.
What is pipe()? pipe() connects one stream to another, automatically transferring data while handling backpressure.
What is Backpressure? Backpressure occurs when a Readable Stream produces data faster than a Writable Stream can consume it. Node.js streams automatically manage backpressure to prevent excessive memory usage.
What is Module Caching? When a module is loaded using require(), Node.js loads and executes it only once. Subsequent require() calls return the cached module.
What is child_process module? The child_process module allows Node.js to create and communicate with other processes, enabling parallel execution of external commands or programs.
Worker Threads vs Cluster? Worker Threads create multiple threads within the same process and can share memory. Cluster creates multiple independent Node.js processes with separate memory spaces.
What is Graceful Shutdown? Graceful Shutdown is the process of stopping an application safely by closing active connections, finishing ongoing requests, releasing resources, and then exiting the process.

🦁 NestJS

Why NestJS? NestJS is a progressive Node.js framework that uses TypeScript by default and follows an Angular‑like architecture. It's highly modular, uses Dependency Injection for decoupling, and supports many transports (HTTP, WebSockets, GraphQL, gRPC). Ideal for enterprise‑scale applications.
Module? A Module is a class decorated with @Module() that organizes the application into cohesive blocks. It groups providers (services), controllers, and imports/exports other modules.
Provider? A Provider is any class that can be injected as a dependency. It's marked with @Injectable() and can be a service, repository, factory, or helper.
Dependency Injection? Dependency Injection is a design pattern where an object's dependencies are provided by an external source rather than created internally. In NestJS, dependencies are declared in the constructor and injected by the framework.
Controller? A Controller handles incoming HTTP requests. Decorated with @Controller(), it contains route handlers using decorators like @Get(), @Post(), @Put(), @Delete().
Service? A Service is a class that contains business logic and data access. It's decorated with @Injectable() and injected into controllers or other services.
Pipe? A Pipe is used to transform or validate data. ValidationPipe uses class-validator to validate DTOs before they reach the controller.
Guard? A Guard determines whether a request should be allowed to proceed to the route handler. Used for authentication and authorization. Implements the CanActivate interface.
Interceptor? An Interceptor adds additional logic around request/response processing. It can transform responses, map errors, or log requests.
Exception Filter? An Exception Filter handles global error handling. It catches exceptions and returns a structured error response consistently across your API.
Request Lifecycle? 1. Middleware → 2. Guards → 3. Interceptors (before) → 4. Pipes → 5. Controller → Service → 6. Interceptor (after) → 7. Exception Filter (if error).
DTO? A DTO (Data Transfer Object) is a TypeScript class that defines the shape of data being sent over the network. It specifies fields, types, and validation rules.
class-validator? class-validator uses decorators to validate class properties. Common decorators: @IsString(), @IsEmail(), @IsNumber(), @Min(), @Max(), @IsOptional().
Swagger? Swagger (OpenAPI) auto‑generates API documentation. Use @nestjs/swagger with decorators like @ApiTags(), @ApiOperation(), and @ApiResponse(). Docs available at /api.
WebSocket? WebSocket support in NestJS uses Gateways decorated with @WebSocketGateway(). They handle real‑time events with @SubscribeMessage().
SSE? Server‑Sent Events allow the server to push events to the client over a single HTTP connection. Use @Sse() decorator returning an Observable.

🔴 Redis

What is Redis? Redis (Remote Dictionary Server) is an in‑memory data structure store used as a database, cache, message broker, and streaming engine. It supports various data structures with sub‑millisecond latency.
What data structures does Redis support? String, Hash, List, Set, Sorted Set, Stream, Bitmaps, HyperLogLogs, and Geospatial indexes.
What is Redis caching? Redis caching stores frequently accessed data in memory to reduce database load and improve response times. Patterns: cache‑aside, read‑through, write‑through, write‑behind.
What is Redis TTL? TTL (Time‑To‑Live) is the expiration time of a Redis key. After TTL expires, the key is automatically deleted. Set using EXPIRE key seconds.
What is Redis persistence? Redis provides persistence to save data to disk for recovery. Two options: RDB (snapshots) and AOF (Append‑Only File). RDB is faster for recovery; AOF is more durable.
What is Redis Pub/Sub? Redis Pub/Sub is a messaging pattern where publishers send messages to channels and subscribers receive them. Used for real‑time notifications and event‑driven architectures.
What is Redis Sentinel? Redis Sentinel is a high‑availability solution for Redis. It monitors instances, performs automatic failover, and provides discovery for clients.
What is Redis Cluster? Redis Cluster is a distributed Redis implementation that shards data across multiple nodes using hash slots (16384 slots). Provides high availability and scalability.
What is ioredis? ioredis is a high‑performance Redis client for Node.js. Supports promises/async, cluster mode, Sentinel, streaming, and Lua scripting.
How to use Redis for rate limiting? Rate limiting uses sliding window or token bucket algorithms. Store a counter per user/IP with TTL, increment on each request, reject if limit exceeded. Use @nestjs/throttler with Redis store.

🍃 MongoDB

What is MongoDB? MongoDB is a document‑oriented NoSQL database that stores data as JSON‑like documents (BSON). It's schema‑flexible, horizontally scalable, and supports rich querying, indexing, and aggregation.
MongoDB vs SQL databases? MongoDB is schema‑less, scales horizontally via sharding, and is good for unstructured data. SQL databases have rigid schemas, use tables/rows, scale vertically, and excel at complex joins and ACID transactions.
What is a collection in MongoDB? A collection is a group of documents in MongoDB, similar to a table in SQL. Collections don't enforce a schema — each document can have different fields.
What is a document in MongoDB? A document is a record in MongoDB, stored as BSON (binary JSON). Each document has a unique _id field (ObjectId by default).
What is MongoDB indexing? Indexing improves query performance using B‑trees. Types: single field, compound, text, geospatial, and hashed.
What is MongoDB aggregation? The aggregation pipeline processes documents through stages: $match, $group, $project, $sort, $lookup, $unwind, $addFields.
What is MongoDB sharding? Sharding is MongoDB's horizontal scaling method that distributes data across multiple shards based on a shard key. Components: shards, mongos, and config servers.
What is MongoDB replica set? A replica set is a group of MongoDB instances maintaining the same dataset for high availability. One primary (writes) and multiple secondaries (replicate). Auto‑failover on primary failure.
What is mongoose? mongoose is the most popular ODM for MongoDB in Node.js. Provides schema validation, type casting, middleware (hooks), and query building.
What is populate in Mongoose? populate() references documents from other collections. Example: User.find().populate('posts') to fetch a user's posts.
What are MongoDB transactions? MongoDB supports multi‑document ACID transactions (since v4.0). Use session.startTransaction() and session.commitTransaction().
What is $lookup? $lookup is an aggregation stage that performs a left outer join with another collection, similar to SQL JOINs.

🐘 PostgreSQL

What is PostgreSQL? PostgreSQL is a powerful, open‑source object‑relational database with strong ACID compliance, advanced features, and excellent performance. Supports JSONB, full‑text search, and extensions.
PostgreSQL vs MySQL? PostgreSQL is more feature‑rich with JSONB, advanced indexing (GIN, GiST, BRIN), custom operators, and better concurrency. MySQL is simpler and often faster for simple reads.
What is JSONB in PostgreSQL? JSONB is a binary JSON data type that stores JSON in decomposed binary format. Faster for indexing and querying. Supports GIN indexing and operators like ->, ->>, @>.
What are PostgreSQL indexes? Types: B‑tree (default), GIN (full‑text, arrays, JSONB), GiST (spatial), BRIN (large tables), Hash, SP‑GiST.
What is a PostgreSQL view? A view is a virtual table based on a query result. Materialized views are physically stored and can be refreshed.
What is a PostgreSQL trigger? A trigger is a function that automatically executes before or after events like INSERT, UPDATE, DELETE. Used for auditing, validation, and enforcing business logic.
What is PostgreSQL full‑text search? Uses tsvector and tsquery for efficient text searching. Supports ranking, stemming, and multiple languages.
What is PostgreSQL isolation level? Read Uncommitted (not allowed), Read Committed (default), Repeatable Read, and Serializable.
What is MVCC in PostgreSQL? MVCC (Multi‑Version Concurrency Control) allows multiple users to read and write simultaneously without blocking. Readers see a consistent snapshot; writers create new versions.
What is EXPLAIN in PostgreSQL? EXPLAIN shows the query execution plan. Use EXPLAIN ANALYZE to see actual runtime and row counts. Essential for performance tuning.
What are PostgreSQL extensions? Popular extensions: PostGIS (geospatial), pgvector (AI/ML vectors), pgcrypto (crypto), UUID‑osp, hstore.

🔧 Prisma

Why Prisma? Prisma is a modern ORM that provides type‑safe database access, auto‑generated TypeScript types, and a fluent API. Makes migrations easy and supports relation management.
Migration? A migration is a declarative way to evolve your schema. Modify schema.prisma then run prisma migrate dev to generate and apply SQL migrations.
Prisma Client? Prisma Client is an auto‑generated query builder providing a fully type‑safe API. Methods: findMany, create, update, delete, transaction.
Prisma Relation? Relations are defined using @relation attributes. Can be one‑to‑one, one‑to‑many, or many‑to‑many. Query with include or select.
Transaction? Prisma supports transactions via $transaction method. Pass an array of queries or a callback. All operations succeed or all fail.
Prisma Middleware? Middleware functions run before or after Prisma Client operations. Used for logging, validation, soft deletes, and auto‑timestamps.

🗄️ Database Concepts

SQL vs NoSQL? SQL databases are schema‑based, support ACID transactions, and excel at complex joins. NoSQL databases are schema‑less, horizontally scalable, and optimized for high write throughput and unstructured data.
Normalization? Normalization organizes data to reduce redundancy and improve integrity. Breaks large tables into smaller related tables. Denormalization adds redundancy for read performance.
Index? An index is a data structure that improves SELECT speed at the cost of slower writes and extra storage. PostgreSQL uses B‑tree by default, plus GIN, GiST, and hash.
Composite Index? An index on multiple columns. Column order matters — most efficient for queries filtering on the first column(s).
Transaction? A transaction is a sequence of operations executed as a single atomic unit. Either all succeed (commit) or none apply (rollback).
ACID? Atomicity: all‑or‑nothing. Consistency: valid state maintained. Isolation: concurrent transactions don't interfere. Durability: committed data persists.
JOIN? A JOIN combines rows from tables based on a related column. Types: INNER, LEFT, RIGHT, FULL OUTER.
Foreign Key? A foreign key references the primary key of another table, enforcing referential integrity and preventing orphaned records.
N+1 Problem? Occurs when an ORM executes 1 query for parents and N for children. Solve with include in Prisma or batch loading techniques.

🔐 Authentication

JWT? JWT (JSON Web Token) encodes claims as a JSON object. Consists of header, payload, and signature. Stateless and ideal for distributed systems.
Access Token? A short‑lived JWT (15‑30 min) used to authorize API requests. Sent in the Authorization header as a Bearer token.
Refresh Token? A long‑lived token (days/weeks) used to obtain new Access Tokens without re‑authentication. Stored in HttpOnly cookies and can be revoked server‑side.
Where to store token? Best practice: HttpOnly, Secure, SameSite=Strict cookies. Avoid localStorage/sessionStorage (XSS‑vulnerable).
CSRF? Cross‑Site Request Forgery tricks a user's browser into making an unwanted request. Mitigations: SameSite cookies, anti‑CSRF tokens.
XSS? Cross‑Site Scripting injects malicious scripts into trusted sites. Mitigations: input sanitization, output encoding, CSP, HttpOnly cookies.
OAuth? OAuth is an open standard for authorization allowing third‑party apps limited access without exposing credentials. Used in "Login with Google" flows.
Google Login? Uses OAuth 2.0. Google returns an authorization code; backend exchanges it for access + ID tokens. ID token contains email/profile.

🧑‍💻 Soft Skills (Backend Focus)

How do you explain a complex backend bug to a non‑technical stakeholder? I focus on impact and timeline, not internals. I say "Users can't complete checkout for ~30 minutes because of a database lock issue. I've isolated it, fix is deploying in 15 minutes." I avoid jargon like "transaction isolation" and instead explain outcomes.
How do you handle a disagreement about API design with a frontend engineer? I listen first — they often see data‑shape pain I don't. I propose a small prototype or a shared schema doc. If we still disagree, I escalate to the tech lead with both options and trade‑offs (payload size, latency, N+1 risk). The goal is the product, not winning.
How do you prioritize when 3 services are down at once? I triage by user impact × revenue impact. Auth first (nobody can log in), then payments, then internal admin. I communicate status in a shared channel every 5 minutes and delegate secondary incidents to teammates instead of context‑switching.
How do you handle receiving critical feedback on your architecture? I separate ego from code. I ask "What would break first with your approach?" to understand their mental model. Then I write a short ADR (Architecture Decision Record) with both options and choose based on evidence, not seniority.
How do you mentor a junior backend developer? I pair‑program on real tickets, not toy problems. I explain the "why" behind patterns (e.g., why we use a repository layer), review their PRs with questions instead of commands, and give them ownership of a small service end‑to‑end.
How do you say "no" to a feature request that would harm system stability? I never say "no" flatly. I say "Yes, and here's the cost: this would add 200ms to every request and require a schema migration. Here are 3 alternatives that achieve the same goal with less risk." Data beats opinion.
How do you stay calm during a production outage? I follow a checklist: (1) confirm impact, (2) stop the bleeding (rollback if possible), (3) communicate, (4) find root cause. I mute Slack noise, focus on one hypothesis at a time, and hand off if I've been on it for over an hour.
How do you collaborate with DevOps on deployment issues? I bring logs, metrics, and a hypothesis, not just "it's broken." I ask what changed recently (env vars, secrets, resource limits) and treat them as partners, not a help desk. I also make sure my app exposes health checks and structured logs.
Tell me about a time you disagreed with a technical decision that was already made. A team chose MongoDB for a financial ledger. I documented my concerns in writing (ACID, reporting joins, data integrity) but committed fully once the decision stood. Six months later we migrated to PostgreSQL — and I led the migration without an "I told you so."
How do you keep your team informed about backend changes? I write short release notes and API changelogs for every breaking change, use feature flags for gradual rollouts, and announce schema migrations in advance. I also run a monthly "backend office hours" where anyone can ask about architecture.
