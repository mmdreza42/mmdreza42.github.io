⚛️ Frontend Interview Q&A JavaScript · TypeScript · Vue · Nuxt · Next.js · React

📘 JavaScript / TypeScript

var, let and const? var is function‑scoped, hoisted and initialized with undefined. let is block‑scoped, hoisted but in the Temporal Dead Zone (TDZ) until initialized. const is block‑scoped and cannot be reassigned (objects/arrays can be mutated).
Hoisting? Hoisting moves declarations to the top of their scope. var is hoisted with undefined. let and const are hoisted but not initialized — accessing them throws ReferenceError due to the TDZ. Function declarations are hoisted entirely.
Closure? A closure is a function that remembers its lexical scope even when executed outside that scope. Used for data privacy, factory functions, and event handlers.
Event Loop? The Event Loop checks the call stack and task queues. When the stack is empty, it takes microtasks (Promises) first, then macrotasks (setTimeout, I/O). Enables non‑blocking concurrency in single‑threaded JS.
Promise vs async/await? Promises use .then()/.catch(). async/await is syntactic sugar making async code look synchronous. Error handling with try/catch instead of .catch().
Call Stack? A LIFO data structure that tracks function calls. Each function is pushed when invoked and popped when returned. Too many nested calls cause a RangeError.
Why TypeScript? TypeScript adds static typing, catching errors at compile time. Provides better IDE support, improves readability, and makes refactoring safer in large codebases.
Interface vs Type? Interface is best for object shapes and is extendable via declaration merging. Type supports unions, intersections, primitives, and mapped types, but no declaration merging.
Generic? Generics create reusable components that work with various types while maintaining type safety. Example: function identity<T>(arg: T): T { return arg; }.
unknown vs any? any disables type checking. unknown is the type‑safe counterpart — you must narrow it with type guards before use.
never? never represents values that never occur. Used for functions that always throw or loop, and for exhaustive type checking.
Utility Types? Partial: all optional. Required: all required. Pick<T,K>: subset. Omit<T,K>: removes. Record<K,T>: key‑value. Readonly: read‑only.

🟢 Nuxt & Vue

What is Nuxt? Nuxt is a Vue.js framework providing SSR, SSG, automatic routing, and modular architecture. Nuxt 3 is built on Vue 3 with the Nitro server engine.
What are Nuxt's rendering modes? SSR (per request), SSG (build time), CSR (browser). Nuxt 3 supports Hybrid Rendering via routeRules.
What is the Nuxt App Router? File‑based routing in pages/. Supports dynamic routes ([id].vue), catch‑all ([...slug].vue), layouts, middleware, and definePageMeta.
What is Vue 3's Composition API? APIs to organize component logic using functions. Uses setup() or <script setup>. Core: ref, reactive, computed, watch, onMounted, provide/inject.
What is <script setup>? Syntactic sugar for Composition API in SFCs. Reduces boilerplate, auto‑exposes top‑level variables to template, and improves performance.
How does Nuxt handle data fetching? Composables: useAsyncData and useFetch (wrapper around useAsyncData + $fetch). Auto caching, key generation, deduplication. Also useLazyFetch / useLazyAsyncData.
What is a Nuxt module? A package that extends Nuxt's functionality (auth, PWA, analytics, CMS). Installed via npm and added to modules in nuxt.config.ts.
Difference between ref and reactive? ref works with any type, wrapped in .value. reactive works only with objects/arrays, no .value, but cannot be destructured without toRefs.
What is computed in Vue? Creates a cached derived state that updates when dependencies change. Lazily evaluated and cached.
What is watch vs watchEffect? watch: observes specific sources, gives old/new values, options: deep, immediate, flush. watchEffect: auto‑tracks dependencies, runs immediately.
How does Nuxt handle authentication? Via @nuxtjs/auth-next or @sidebase/nuxt-auth. Provide useSession(), signIn(), signOut(), and route middleware.
What is the Nuxt server/ directory? Where server‑side logic lives: API routes (server/api/), middleware, plugins. Enables full‑stack apps with type‑safe useFetch.
What are Nuxt composables? Reusable functions in composables/, auto‑imported. Examples: useState, useRouter, useRoute, useHead.
SSR vs SSG in Nuxt? SSR: server renders per request (dynamic). SSG: pre‑rendered at build (static, faster). Nuxt 3 routeRules mixes modes per route.
How does Nuxt handle SEO? useHead composable for meta tags, titles, links. Supports Open Graph, JSON‑LD, sitemaps. SSR renders meta on server for crawlers.
What are Nuxt plugins? Files that run before the app is created. Register global components, add libraries, inject values, run startup logic. Set ssr: false for client‑only.
What is the nitro server? Nuxt 3's universal server engine. Runs on Node.js, Deno, Bun, Cloudflare Workers. Supports file‑based API routes, server middleware, caching, and static output.

🟢 Vue.js

What is Vue.js? A progressive JavaScript framework for building UIs. Reactive data binding, component‑based architecture, virtual DOM. Known for gentle learning curve.
What are Vue's key features? Reactivity (Proxies in Vue 3), component‑based architecture, template syntax (v-if, v-for, v-model), Composition API, SFCs, Vue Router, Pinia, SSR via Nuxt.
Difference between Vue 2 and Vue 3? Vue 3: Proxy‑based reactivity, Composition API, faster rendering, smaller bundle, TypeScript support, fragments, Teleport, Suspense.
Options API vs Composition API? Options API: classic, uses data, methods, computed. Composition API: functions, better logic reuse, cleaner for complex components, better TS inference.
What is a Single‑File Component (SFC)? A .vue file with <template>, <script>, and <style>. Self‑contained, scoped CSS, maintainable.
What are Vue directives? Special attributes with v- prefix: v-if, v-for, v-model, v-bind (:), v-on (@), v-show, v-html, v-cloak.
How does Vue 3's reactivity work? Built on JavaScript Proxies. Intercepts get/set to track dependencies and schedule updates. More efficient than Vue 2's Object.defineProperty.
What is the ref function? Creates a reactive reference to a value, wrapped in .value. Works with any type. Auto‑unwrapped in templates.
What is the reactive function? Creates a deeply reactive object using a Proxy. Objects/arrays only. Cannot destructure without toRefs.
Difference between ref and reactive? ref: any type, .value wrapper, more flexible. reactive: objects/arrays only, no .value, no destructuring without toRefs.
What are Vue slots? Content distribution mechanism. Default, named (<slot name="header" />), and scoped slots. Enable flexible reusable components.
What are provide and inject? Dependency injection allowing parent components to pass data to any descendant without props. Useful for theme, auth, config.
What is Pinia? Official state management for Vue, replacing Vuex. Simpler, type‑safe, Composition API friendly. Uses defineStore() with state, getters, actions.
Vuex vs Pinia? Vuex: older, mutations, actions, modules, more boilerplate. Pinia: no mutations, better TS, simpler API, modular, recommended.
What is Vue Router? Official routing library for SPAs. Features: nested routes, dynamic matching, named routes, params, query, navigation guards, lazy loading.
What are navigation guards? Middleware functions controlling navigation: global (beforeEach, afterEach), per‑route (beforeEnter), in‑component (beforeRouteEnter, etc.).
What is lazy loading in Vue? Loading JS chunks only when needed via dynamic imports: () => import('@/views/Home.vue') or defineAsyncComponent(). Reduces initial bundle.
What is Vue's Teleport? Renders content outside the current component's DOM — useful for modals, tooltips. <Teleport to="body">.
What is Vue's Suspense? Manages async dependencies in the component tree. Shows fallback while nested async components resolve. Works with SSR.
What are Vue composables? Reusable functions encapsulating reactive logic. Naming: useXxx(). Can use reactivity functions and compose together.
What is v-model and two‑way binding? Creates two‑way binding between inputs and reactive data. Sugar for :value + @input. Custom components use modelValue / update:modelValue.
v-if vs v-show? v-if: destroys/re‑creates elements. Better for stable conditions. v-show: toggles CSS display. Better for frequent toggling.
What is <KeepAlive>? Caches inactive component instances instead of destroying them. Uses activated and deactivated hooks. Configurable with include/exclude.
Vue vs React? Vue: HTML templates, directives, Proxy reactivity, gentler curve, official Nuxt. React: JSX, more flexible, hooks, manual dep tracking, official Next.js.

⚡ Next.js

App Router? New file‑based routing in app/ (Next 13+). Supports nested layouts, server components, loading/error boundaries, and parallel/intercepting routes. Replaces Pages Router.
Server Component? Rendered on the server, never sent to client. Can be async, access DBs directly. Cannot use hooks or browser APIs. Ideal for data fetching and static content.
Client Component? Hydrated on client, provides interactivity. Marked with "use client". Can use hooks, event listeners, browser APIs.
Server vs Client Component? Server components reduce client bundle and access backend. Client components provide interactivity. Server can import Client, but Client cannot import Server directly.
When to use "use client"? When needing hooks, browser APIs, or client‑side libraries. Also for event handlers and interactive UI.
SSR / SSG / ISR / CSR? SSR: per request. SSG: build time. ISR: SSG with revalidation. CSR: browser after initial load.
Metadata API? Define <head> via metadata export or generateMetadata in layout.tsx/page.tsx. Supports static and dynamic metadata.
Route Handler? API endpoints in route.ts files inside app/. Export GET, POST, etc. Equivalent of Pages Router API routes.
Middleware? Runs before requests complete. Used for auth, redirects, rewrites, headers, logging. Runs on Edge runtime. Configurable matcher.
Authentication in Next? Used NextAuth.js (Auth.js) with built‑in providers and session management. Alternative: custom JWT with iron-session and middleware route protection.
Why NextAuth? Built‑in OAuth providers, session handling, CSRF protection, JWT + DB sessions, Server Components support, token rotation.
Dynamic Routing? Square brackets in folder names: app/blog/[slug]/page.tsx. Access via params. Catch‑all: [...slug], optional: [[...slug]].
Loading.tsx / Error.tsx? Loading.tsx: fallback UI wrapped in Suspense. Error.tsx: catches errors and displays custom error UI. Both per‑route or global.
Suspense / Streaming? Suspense: shows fallback while children load. Streaming: sends HTML chunks as ready, improving TTFB and perceived performance.

⚛️ React

Why Virtual DOM? A lightweight in‑memory representation of the DOM. React diffs the new tree against the old and updates only changed nodes, batching expensive DOM operations.
useMemo / useCallback / React.memo? useMemo: caches computed values. useCallback: caches function references. React.memo: prevents re‑render if props haven't changed (shallow comparison).
Context API? Passes data through the tree without prop drilling. Good for global state (theme, auth, language). Can cause unnecessary re‑renders when context value changes.
Zustand? Lightweight state management with minimal boilerplate. Creates stores, selectively re‑renders only components using updated state. More scalable than Context for complex state.
TanStack Query (React Query)? Server‑state management library. Handles fetching, caching, syncing, updating. Features: background refetch, pagination, infinite queries, optimistic updates.
Why React Query? Manages the entire lifecycle of server state: caching, background updates, retries, stale‑while‑revalidate. Reduces network requests and boilerplate.
Cache in React Query? Stores fetched data with metadata: staleTime (how long fresh) and cacheTime (how long in cache after unused). Auto‑updates in background.
invalidateQueries? Marks cached queries as stale, triggering background refetch. Used after mutations to sync UI with latest server state.

🧑‍💻 Soft Skills (Frontend Focus)

How do you handle a designer's request that would hurt accessibility? I educate, don't dictate. I show them how screen readers announce their design and propose an alternative that keeps the visual intent but fixes contrast/focus order. I frame it as "here's how more users can enjoy your design."
How do you push back on a PM who wants a feature that will slow down the app? I bring data: Lighthouse scores, bundle size delta, or a quick prototype benchmark. I offer alternatives (lazy load, feature flag, smaller scope) and let them decide with full information. I never just say "it's slow."
How do you explain a rendering performance issue to a backend engineer? I show the waterfall chart and point to the specific slow API. I say "this endpoint takes 1.2s and blocks our initial render." I avoid React jargon and focus on the shared goal: fast user experience.
How do you handle a disagreement about state management (Redux vs Context vs Zustand)? I ask about the actual pain: is it re‑renders, boilerplate, or debugging? I propose a small experiment: migrate one feature and measure bundle size + dev velocity. Let the evidence decide.
How do you mentor a junior frontend developer? I pair on real UI tickets, explain why we use certain patterns (e.g., why useCallback here), review PRs with questions, and give them ownership of a small component or page end‑to‑end.
How do you handle a UI bug that only happens on Safari? I reproduce first, then isolate: is it CSS, JS, or polyfill? I check caniuse.com, test a minimal case in Safari, and document the fix with a comment so nobody removes it later. I never guess.
How do you stay calm when a critical UI bug hits production? I follow a checklist: (1) confirm scope (all users or a subset?), (2) roll back if possible, (3) communicate in the incident channel, (4) fix forward. I mute Slack noise and focus on one hypothesis at a time.
How do you collaborate with backend engineers on API changes? I share the frontend contract early: "I need user.avatarUrl as a string, not null." I use TypeScript types, mock servers, and OpenAPI specs. I treat the API as a shared product, not a black box.
Tell me about a time you disagreed with a UI/UX decision. A PM wanted infinite scroll on a settings page. I documented my concerns in writing (discoverability, back button, accessibility) but committed once the decision was made. Later we A/B tested and switched to pagination — and I led the change without an "I told you so."
How do you keep your team informed about frontend changes? I write short changelogs and design notes for every breaking UI change, use feature flags for gradual rollouts, and share before/after screenshots. I also run a monthly "frontend guild" where anyone can ask about patterns.
