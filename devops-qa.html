🐳 DevOps Interview Q&A Docker · Git · REST · Security · Architecture

🐳 Docker

Docker? Docker is a containerization platform packaging apps and dependencies into lightweight, portable containers. Solves "works on my machine" and enables easy deployment, scaling, and isolation.
Image? A Docker image is a read‑only template with app code, runtime, libraries, and dependencies. Built from a Dockerfile, stored in registries (Docker Hub). Blueprint for containers.
Container? A runnable instance of an image. Isolated but shares the host kernel — lighter than VMs. Has its own filesystem, network, and process space.
Dockerfile? A text file with build instructions. Common: FROM, WORKDIR, COPY, RUN, EXPOSE, CMD.
docker compose? Tool for multi‑container apps. Uses docker-compose.yml to configure services, networks, volumes. Start all with docker-compose up.
Multi‑stage Build? Reduces final image size using multiple FROM stages. Example: build stage with full toolchain, runtime stage with only production dependencies.
Volume? Persistent storage surviving container restarts. Used for databases, uploads. Managed independently from container lifecycle.
Port Mapping? Maps container port to host port with -p, e.g., -p 3000:3000. Without it, services are only reachable inside the container network.

📦 Git

Git Flow? Branching model: main (production), develop (integration), feature (new work), release (prep), hotfix (emergency). Structured but can be heavy for small teams.
merge? Combines branches with a new commit having both as parents. Preserves history, non‑destructive. Merge commits can clutter history.
rebase? Rewrites commit history by moving commits to a new base. Creates linear history. Destructive — never rebase shared branches.
cherry‑pick? Applies a specific commit from one branch to another without merging. Useful for hotfixes. Can create duplicate commits.
stash? Saves uncommitted changes temporarily, reverting working dir to last commit. Reapply with git stash pop or apply.
conflict? Occurs when two branches modify the same part of a file. Resolve manually, git add, and complete merge/rebase.

🌐 REST API

REST? An architectural style using stateless, cacheable HTTP. Resources identified by URLs, manipulated with GET, POST, PUT, PATCH, DELETE. Emphasizes scalability and uniform interface.
PUT vs PATCH? PUT: replaces entire resource. PATCH: partial update. PUT is idempotent; PATCH is not necessarily.
POST vs PUT? POST: creates new resource, not idempotent. PUT: updates/replaces at a URI, idempotent.
Status Codes? 200 OK, 201 Created, 204 No Content, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict, 422 Unprocessable, 500 Server Error.
Pagination? Offset‑based: ?page=2&limit=20 — simple but slow at large offsets. Cursor‑based: ?cursor=abc&limit=20 — scalable, ideal for real‑time feeds.
Filtering? Query params: ?status=active, ?price[gte]=100, ?q=search. Implement with Prisma's where clause for dynamic safe filters.
Sorting? Use ?sort=field:direction, e.g., ?sort=createdAt:desc. Multiple fields: ?sort=createdAt:desc,name:asc. Maps to Prisma's orderBy.
Versioning API? Strategies: URL (/api/v1/users), header (Accept-Version: v1), query (?version=1). URL versioning preferred for clarity.
Rate Limiting? Controls request count per time window. Use @nestjs/throttler with Redis. Return 429 Too Many Requests when exceeded.

🛡️ Security (OWASP)

OWASP Top 10? Most critical web app risks: Broken Access Control, Cryptographic Failures, Injection, Insecure Design, Security Misconfiguration, Vulnerable Components, Identification Failures, Data Integrity Failures, Logging Failures, SSRF.
XSS? Malicious scripts injected into trusted pages. Mitigations: input sanitization, output encoding, CSP, HttpOnly cookies.
SQL Injection? User input improperly concatenated into SQL. Prevention: parameterized queries, ORMs (Prisma), validate/whitelist input.
CSRF? Tricks browser into making unwanted requests. Prevention: SameSite cookies, anti‑CSRF tokens, double‑submit cookies. JWT in headers naturally mitigates.
Rate Limiting? Restricts requests per client. Prevents brute‑force and DoS. Use @nestjs/throttler with Redis.
Password Hashing? Convert passwords to one‑way hashes. Use bcrypt (salted, slow). Never store plaintext.

🧠 Architecture

MVC? Design pattern with Model (data/logic), View (UI), Controller (input handling). In backend, View is JSON responses.
Layered Architecture? Organizes code into horizontal layers: Presentation, Business Logic, Data Access, Database. Improves maintainability and testability.
Repository Pattern? Abstracts data access behind a collection‑like interface. Easier to switch DBs, mock for tests, centralize queries.
SOLID? Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion. Makes code maintainable and scalable.
Design Patterns used? Singleton (PrismaClient), Factory (service factories), Observer (events), Strategy (payment/auth strategies).
Why Dependency Injection? Decouples classes from dependencies. Enables mocking in tests and swapping implementations without changing the class.

🧑‍💻 Soft Skills (DevOps Focus)

How do you handle a deployment that broke production at 3 AM? I roll back first, investigate later. Then I follow the incident checklist: confirm impact, communicate in the channel, isolate the change. I write a blameless post‑mortem the next day and add a canary stage to prevent recurrence.
How do you convince a team to adopt Docker / CI/CD? I show, don't tell. I containerize one service, measure "time from commit to prod" before and after, and share the results. I also do a lunch‑and‑learn where teammates can try it themselves. Adoption follows value, not mandates.
How do you handle a developer who keeps pushing broken code? I add guardrails, not blame: pre‑commit hooks, required CI checks, and PR templates. I also pair with them once to understand their workflow. Often it's a missing local test setup, not carelessness.
How do you explain infrastructure cost increases to non‑technical leadership? I use dollars and graphs, not technical terms. "Our cloud bill went up 30% because traffic doubled and we're running 3 extra database replicas for reliability. Here are 3 options to reduce cost without hurting uptime."
How do you mentor a junior DevOps engineer? I pair on real incidents, let them lead the rollback while I observe, and review their IaC PRs with questions. I also give them ownership of one service's pipeline end‑to‑end.
How do you say "no" to a request that would compromise security? I never say "no" — I say "here's the risk and here's a safer alternative." For example: "Opening that port exposes our DB to the internet. Instead, let's use a bastion host or VPN — same access, much lower risk."
How do you stay calm during a multi‑service outage? I follow a triage checklist: which services are affected? What's the shared dependency? I delegate investigation to teammates, keep one person on comms, and I focus on the highest‑impact fix first.
How do you collaborate with developers who don't care about infrastructure? I make the right thing the easy thing: provide a docker-compose up that just works, a template Dockerfile, and a one‑command local environment. When infra is frictionless, developers naturally adopt it.
Tell me about a time you disagreed with a deployment strategy. A team wanted big‑bang deploys on Fridays. I documented my concerns in writing (no rollback plan, weekend on‑call) but committed. After one bad Friday deploy, we moved to blue‑green with automated rollback — and I led the migration without an "I told you so."
How do you keep the team informed about infrastructure changes? I write short change logs and runbooks for every infra change, announce in advance in the team channel, and use feature flags for gradual rollouts. I also run a monthly "infra office hours" for questions.
